# Migration plan: split web/mobile, web to Angular (2026-11-12)

Branch `refactor/angular-web`, cut from `feat/mobile-native-redesign` @ 323b243 (clean tree, nothing uncommitted).

## Audit

| Area | Before |
|---|---|
| Web | Not a separate app. The Expo app itself, rendered by `react-native-web`, exported with `expo export -p web` (Metro), deployed by Vercel from the repo root. Wide layout at >= 1024px (icon rail, top bar quick add, task side panel); below that the phone layout. |
| Mobile | Same Expo app: Expo SDK 58, React Native 0.88, React 19.3, Expo Router 58 (typed routes), development builds only (Android `com.hieucoconut02.taskapp`, `/android` generated by CNG, gitignored). |

| Shared code | Everything was shared, since web and mobile were one codebase. Framework-free: `src/lib/{dates,journal,tags,quick,subtasks,reports,html,accent,i18n}.ts`, DB row types in `supabase.ts`, `components/dom/sanitize.ts`. |
| Scripts | `start/web/ios/android` (expo), `lint` (expo lint), `typecheck` (tsc), `test` (`node src/lib/logic.check.ts`), `db:push`. |
| Env | `.env.local`: `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_KEY`, `SUPABASE_DB_PASSWORD` (db script only). |
| Path coupling | `app.json` font paths `./node_modules/...`, `tsconfig` `@/*` → `./src/*`, `logic.check.ts` scans `src` relative to cwd, `vercel.json` at root, `.gitignore` `/android` `/ios`, Claude hooks check `src/`. |

## Target

```
apps/web/        Angular 21 (LTS) app, standalone components, signals, lazy routes
apps/mobile/     the Expo app, moved as is
packages/core/   framework-free domain logic + row types + i18n (used by web; see "Sharing")
supabase/        backend (unchanged location: the Supabase CLI expects it there)
scripts/         backend tooling (db push)
docs/            architecture, api, development, migration
```

Angular 21, not 22: Angular 22 requires Node ^22.22.3, this machine (and the repo) runs Node 22.20.0. 21 is the current LTS line and supports Node ^22.12.

No npm workspaces: Expo/Metro and the Angular CLI each keep their own `node_modules` and lockfile, so neither install can disturb the other. The root `package.json` only forwards commands.

## Sharing

`packages/core` holds the pure modules (copied from `apps/mobile/src/lib`, unchanged logic) and their node:assert check. The web imports it through a tsconfig path. The mobile app keeps its own copies under `apps/mobile/src/lib`: pointing Metro at a folder outside the app needs `watchFolders`/resolver changes and a native rebuild to verify, which the task forbids for mobile. Unifying mobile onto `packages/core` is a follow-up (see docs/architecture/overview.md).

## Steps

1. `git mv` the Expo app into `apps/mobile`; fix only path-bound config (gitignore, tsconfig include, test scan path, env file location).
2. Create `packages/core` from the pure libs; run its check.
3. Scaffold `apps/web` (Angular CLI 21, strict, SCSS, routing, ESLint, Prettier, Vitest unit tests, Playwright e2e).
4. Core services: Supabase client, auth (session signal, guards, recovery), live rows (realtime + refresh), notifications (toasts with undo, confirm dialog), i18n pipe, prefs (theme/accent/lang).
5. Features: auth, today, upcoming, inbox, projects, project detail, journal, stats, search, reports, report editor, settings, task drawer, quick add, design system.
6. Redesign (Hallmark), responsive at 1920/1440/1366/768/390/360, dark mode.
7. Vercel: build `apps/web` instead of `expo export`.
8. Verify: lint, typecheck, unit, e2e, production build, browser pass at every viewport, mobile `expo export` + `tsc` + its tests.
9. Docs.
